# 💓 نبضة

لعبة مسابقة حيّة تُقام في قاعة. يتنافس اللاعبون في وقتٍ واحد، كلٌّ من جهازه ومعه عدّادٌ
تنازليّ هو نبضه. الإجابة الصحيحة تضيف وقتاً والخاطئة تخصم، وتنتهي الجولة على الجميع حين
يتوقف نبض ثُمن القاعة. وبين الجولات يشتري اللاعبون بطاقاتٍ بالشرارات يدعمون بها أنفسهم
أو يهاجمون غيرهم.

الهوية: مخطّط نبضات القلب. كلما نفد الوقت خفتت النبضات حتى يستقيم الخط ويسكن النبض.

## الأسماء المستعارة

يدخل اللاعب باسمين: **اسمه في اللعبة**، مستعاراً يراه الجميع ويمكن أن يكون أيّ شيء، و**اسمه
الحقيقي** وهو مطلوب. فلا يعرف أحدٌ من يجمّده ومن يبارزه حتى النهاية.

- الاسمُ الحقيقي لا يغادر السيرفر إلا إلى المنظّم، في قناته وحده (كالإجابة الصحيحة)، ويراه
  بخطٍّ صغير تحت كل مستعارٍ في لوحة **ترتيب الفوز**.
- بعد إعلان الأوائل يظهر للمنظّم زرُّ **كشف الأسماء**: كلُّ ضغطةٍ خطوة — الثالثُ ثم الثاني
  ثم الأول ثم البقيّة دفعةً واحدة. والاسمُ الحقيقي يظهر في لوحة «ترتيب الأوائل» نفسها، تحت
  المستعار بخطٍّ صغير، على شاشة العرض وجوّالات اللاعبين في اللحظة نفسها.
- الاسمُ الحقيقي بقدر الاسم الثنائي (عشرون حرفاً)، والطويلُ يلتفّ إلى سطرٍ ثانٍ ولا يُقصّ.
- الاسمُ الحقيقي محفوظٌ مع لقطة الغرفة في القاعدة.

## الجولة

- **العدّاد**: يبدأ كل لاعبٍ بـ٣٠ ثانية. الصحيحة +٥ ثوانٍ، والخاطئة −٣، والسقف ١٢٠ ثانية.
  والأسئلة تتوالى على كل لاعبٍ وحده، فلا ينتظر أحدٌ أحداً.
- **نهاية الجولة (قاعدة الثُّمن)**: تنتهي الجولة حين يتوقف نبض `ceil(عدد اللاعبين ÷ ٨)`
  منهم، أو حين لا يبقى نبضٌ حيّ. فمن كانوا ثمانيةً فأقلّ تنتهي جولتهم بأول من يتوقف،
  وبعشرين لاعباً بثالثهم، وبستين بثامنهم. وكلُّ نبضةٍ من هذه مربّعٌ يُرى في ترويسة
  اللاعب ولوحة المنظّم وشاشة العرض، ينكسر باسم من توقف.
- **من توقف نبضه** والجولة جارية يتابعها مشاهداً حتى تنتهي.
- **الاستراحة**: دقيقةٌ ونصف بعد كل جولة للشراء، يراها اللاعب عدّاداً تحت بطاقته. فإذا
  انقضت أُغلق المتجر حتى يبدأ المنظّم الجولة التالية. وتحت المتجر نبضُ اللاعبين مرتّباً
  بالأكثر ثوانيَ، ومن توقف نبضه آخرَهم.

## النقاط

نقاط الفوز هي التي تصنع الترتيب، وتُحتسب عند نهاية الجولة لا أثناءها:

- **من صمد حتى النهاية** يأخذ نقطةً عن كل إجابةٍ صحيحة، ونقاطَ مركزه بحسب الوقت الباقي
  له: الأول ٥ ثم ٤ ثم ٣ ثم ٢ ثم ١ لكل من بعدهم (وإن كانوا أقلّ من ستة فالأول يأخذ عددهم
  ناقص واحد).
- **من توقف نبضه** لا يأخذ شيئاً في تلك الجولة، ولا عن إجاباته الصحيحة: الجولة تُكسب
  بالبقاء حتى آخرها.
- **المضاعفة** تضرب نقاط الصامد في ٢، وتسقط إن توقف نبضه.
- **التعادل** في الترتيب يُكسر بمجموع الإجابات الصحيحة في اللعبة كلها.
- وللمنظّم أن يعدّل نقاط لاعبٍ أو وقته يدوياً.

## الشرارات

عملة الشراء، منفصلةٌ عن نقاط الفوز فلا يخسر من يشتري شيئاً من ترتيبه:

- **٣ شرارات** لكل من لعب الجولة، ولو توقف نبضه، فلا يبقى أحدٌ مفلساً.
- **شرارتان** لكل ٣ إجاباتٍ صحيحةٍ متتالية. والخطأ يقطع السلسلة، ولو وقاه الدرع.

فيكسب اللاعب الوسط نحو أربع شراراتٍ في الجولة، والأقوى نحو سبع.

## متجر البطاقات

يُفتح في الاستراحة بين الجولات، وأثر البطاقة في الجولة التالية. ثماني بطاقات في ثلاث
فئات، ولكل بطاقةٍ حدٌّ من المرّات طوال اللعبة (وللمنظّم أن يصفّر العدّادات من لوحته):

| دعم | ⚡ صاعق القلب | إن توقف نبضك عاد من نفسه بـ٢٠ ثانية، مرّةً في الجولة | 5 | 2 |

| هجوم | ⚔️ مبارزة | تتحدى لاعباً **أعلى منك نقاطاً**، فإن أصبت في الجولة أكثر منه سرقت منه ٧ نقاط | 7 | 3 |

**تفاصيل المبارزة:**

- لا تُبارز إلا من هو أعلى منك في النقاط، فلا يستقوي المتقدّم على من خلفه.
- اللاعب يُتحدّى **مرّةً واحدةً في الجولة**: أول من يتحدّاه يحجزه، ومن بعده يراه محجوزاً.
  فلا يتكالب على المتصدّر ثلاثةٌ أو أربعة.
- تُحسم عند نهاية الجولة بعدد الإجابات الصحيحة. إن لم يغلب المتحدّي فلا شيء على أحد،
  وخسر هو ثمن البطاقة وحده. ونقاطها لا تُضاعف ولا يُسقطها توقف النبض.
- المرآة لا تردّها: هي تحدٍّ يلعبه الاثنان، لا ضربةٌ تقع على أحدهما.
- تُعلن عند العدّ قبل الجولة: بطاقةٌ فيها الاسمان، يجري من كلٍّ منهما خطُّ نبضٍ إلى الوسط
  فيظهر السيفان. المتحدّي يميناً والمتحدّى يساراً. على شاشة العرض أعلاها، وإن تعدّدت
  المبارزات صُفّت عمودين حتى ستٍّ ويُذكر عددُ ما زاد. وعلى جوّالي الطرفين «أنت» مكان الاسم.

**الشراء:** ضغطةٌ تشتري وضغطةٌ أخرى تتراجع ما دام وقت الشراء قائماً. والضغط المطوّل على
البطاقة يفتح تفصيلها في نافذةٍ سفلية تُغلق بسحبها نزولاً أو بالنقر خارجها.

الأسعار مقيسةٌ بدخل الجولة: اللاعب الوسط يكسب نحو أربع شرارات، فبطاقةٌ بخمسٍ قرارُ
جولةٍ أو جولتين، والمضاعفة والمبارزة بسبعٍ رهانٌ يُدّخر له. والتفصيل في تعليق `CARDS` في
`server/game.js`، وهو المرجع الوحيد للأسعار والحدود.

## التشغيل محلياً

النبضة تحفظ سجلّها في PostgreSQL ولا تُقلع بلا رابط قاعدة. فإن لم تكن عندك
واحدة، فهذا يُنزل محرّكاً مستقلاً ويشغّله ويكتب رابطه في `.env` — بلا تثبيتٍ
ولا صلاحية مدير:

```bash
npm run db           # نافذةٌ تبقى مفتوحة — القاعدة على 55432
```

ثم في نافذةٍ أخرى:

```bash
npm install          # اعتماديات السيرفر
npm run build        # بناء الواجهة
npm start            # http://localhost:3000
```

للتطوير مع إعادة التحميل التلقائي (نافذةٌ ثالثة):

```bash
npm run dev          # السيرفر على 3000
npm run dev:client   # الواجهة على 5173 (تمرّر الطلبات إلى 3000)
```

والصفحات: `/` التعريف · `/admin` المنظّم · `/play` اللاعب · `/display` العرض ·
`/console` المالك (بمفتاح `NABDA_OWNER_KEY` من `.env`).

## إدارة الجولة

- **إيقاف واستئناف**: العدّادات تسكن تماماً (مسافة في لوحة المفاتيح).
- **إعادة الجولة من أوّلها** (أثناء الجولة): لعطبٍ يصيب اللعب، كجهاز لاعبٍ يعلّق أو شبكةٍ
  تسقط أو سؤالٍ يُقرأ سهواً بصوتٍ عال. تُوقف الجولة وتُعاد بضغطتين، الثانية للتأكيد.
  رقمُ الجولة لا يتقدّم، ونقاطُها لم تُحتسب بعد (الاحتساب عند نهاية الجولة)، وآثارُ
  البطاقات تُردّ كما كانت.
- **تعديل البنوك** (بين الجولات): يُختار ما يُلعب به من البنوك ثم يُعتمد.
- **الداخل أثناء الجولة** يُسجَّل منتظِراً: لا يُسأل ولا ينزل عدّاده ولا يُحتسب في
  نقاط الجولة الجارية، ويدخل اللعب مع بدء الجولة التالية.
- **نبضات الجولة**: لوحةٌ تُريه كم نبضةً تنهي الجولة، وكل نبضةٍ انكسرت باسم صاحبها.
- **ترتيب الفوز** في اللوحة يتغيّر بنهاية الجولة، لا مع كل تعديلٍ يدويّ.
- **إنهاء اللعبة** يعلن الأوائل بمجموع النقاط في لوحة «ترتيب الأوائل»، ثم يكشف المنظّم الأسماء
  الحقيقية خطوةً خطوة. وتبقى اللوحة على جوّال اللاعب ولو انقطع اتصاله وعاد، ولا تُطوى جلستُه
  إلا بزرّي الخروج. وعلى شاشة العرض تُصغَّر اللوحة كلُّها حتى تسعها الشاشة، فلا يضيع آخرُ
  الترتيب في قاعةٍ كبيرة.
- كل زرٍّ لا رجعة فيه يعمل بضغطتين، الثانية للتأكيد.
- في أول دخولٍ للوحة المنظّم، وأول استراحةٍ للاعب، جولةٌ تعريفيةٌ قصيرة تشير إلى أجزاء
  الشاشة.

## البنية

```
server/          سيرفر Node + Socket.IO — المرجع الوحيد للوقت والنتائج
  game.js        منطق اللعبة: الغرف، العدادات، النقاط، الشرارات، البطاقات
  banks.js       البنوك: تُقرأ من PostgreSQL وتُحفظ فيه، والملفّات بذرة
  banks/*.json   بذرةُ البنوك ونسخةُ احتياطها — لا مرجعَها
  pull-banks.mjs يسحب البنوك من الموقع الحيّ إلى الملفّات
client/          واجهة React + Vite + Tailwind
```

**قرارات تصميمية مهمة:**

- **الوقت يُحسب في السيرفر فقط** (نبضة كل 250 مللي‑ثانية). المتصفح يعرض ويُنعّم الحركة
  محلياً لكنه لا يقرر شيئاً — يمنع الغش ويوحّد كل الشاشات.
- **الإجابة الصحيحة لا تغادر السيرفر** قبل انتهاء الجولة، حتى لا تُقرأ من أدوات المطور.
- **الغرفة الجارية في الذاكرة** — الوقت يُحسب كل ٢٥٠ مللي ولا يحتمل رحلةً إلى قاعدة،
  وتُحذف الغرف الخاملة بعد ساعتين. أما السجلّ (الغرف وإحصاؤها، البلاغات، التعليقات،
  قياس الأسئلة) **ونصُّ البنوك** فيُكتب في **PostgreSQL** عبر `DATABASE_URL`.
- **ما كُتب على قرص الحاوية لا يُعتمد عليه** — كلُّ نشرٍ يبني حاوياً جديداً. ولذلك
  انتقل السجلّ من SQLite، ثم انتقلت البنوك.

## النشر

> [!IMPORTANT]
> **شغّل نسخة واحدة فقط** (بلا autoscaling أو replicas). حالة اللعبة في ذاكرة العملية،
> فلو عملت نسختان قد ينضم فريق لواحدة وفريق لأخرى ولا يرى أحدهما الآخر.

المنصة يجب أن تدعم **الخوادم الدائمة و WebSocket** — فالمنصات الـ serverless لا تصلح،
لأن الحالة في الذاكرة و`setInterval` والاتصال الدائم لا تعيش فيها.

**ما تحتاجه المنصة:**

| | |
|---|---|
| البناء | `npm run build` |
| التشغيل | `npm start` |
| فحص الصحة | `/api/health` |
| Node | **٢٤ فأعلى** (مثبَّت في `.node-version`) |
| النسخ | **واحدة فقط** — بلا autoscaling ولا replicas |
| قاعدة | **PostgreSQL** مُدارة في نفس المنطقة — واربطها بالتطبيق فيُحقن رابطُها |

السيرفر يقرأ المنفذ من `PORT` تلقائياً.

### متغيّرات البيئة

| المتغيّر | | |
|---|---|---|
| `DATABASE_URL` | رابط PostgreSQL للسجلّ | **مطلوب** — بلا رابطٍ لا يُقلع السيرفر |
| `NABDA_OWNER_KEY` | مفتاح لوحة المالك على `/console` | **اضبطه** — وإن تُرك فارغاً وُلّد مفتاحٌ مؤقّت عند كل تشغيل وطُبع في السجلّ، فيتبدّل مع كل نشر |
| `PORT` | منفذ السيرفر | تضبطه المنصة عادةً |
| `PGSSL=off` | تعطيل تعمية الاتصال | للقاعدة المحليّة وحدها — والتعمية تُطفأ من نفسها على `localhost` |

> [!WARNING]
> **لماذا قاعدةٌ خارجية ولم يعد ملفّاً؟** كان السجلُّ ملفَّ SQLite في `server/`،
> والمنصّات تبني حاوياً جديداً عند كل نشر فيُمحى معه. وCranL لا تقدّم أقراصاً
> دائمة — الموجود دِلاء S3 (تخزينُ كائنات، لا نظام ملفات) وقواعدُ مُدارة. فالسجلّ
> الآن خارج الحاوية يعيش ما دامت القاعدة.

**للتطوير محلياً** — ثلاثُ قواعد: واحدةٌ للّعب واثنتان للفحوص.

`npm run db` يُنشئها كلّها ويكتب رابط `nabda` في `.env`. وهو يُنزل محرّك
PostgreSQL أوّلَ مرّة في `%LOCALAPPDATA%\nabda-pg` — **خارج المشروع**، لسببين:
ثنائيّاتُ بوستجرس لا تقرأ مساراً فيه حرفٌ غير لاتينيّ (ومسارُ هذا المشروع
عربيّ)، والمشروعُ في OneDrive ومزامنةُ ملفّات قاعدةٍ مفتوحةٍ تُفسدها. ولا يدخل
`package.json` كي لا يُنزَّل في بناء المنصّة.

وإن كان عندك بوستجرس مثبَّت فهو أولى — تجاهل `npm run db` واكتب رابطك:

```bash
createdb nabda nabda_test nabda_e2e
DATABASE_URL=postgres://localhost/nabda npm start
```

`memory-test` يمسح مخطَّط `nabda_test` قبل كل تشغيل، ويرفض أيَّ قاعدةٍ لا يحوي
اسمُها «test» — فلا يمحو إنتاجاً بالخطأ. وللفحوص على قاعدة `npm run db`:

```bash
NABDA_TEST_DB=postgres://nabda:nabda@localhost:55432/nabda_test npm test
```

## إضافة بنك أسئلة

البنك يُنشأ من لوحة المالك (أدناه). أما ملفّات `server/banks/` فبذرةٌ تُزرع مرّةً حين
تكون القاعدة فارغة، وشكلها:

```json
{
  "id": "sports",
  "name": "رياضة",
  "questions": [
    { "q": "كم عدد لاعبي فريق كرة القدم؟", "options": ["9", "10", "11", "12"], "answer": 2, "level": 1 }
  ]
}
```

`answer` رقم الخيار الصحيح بدءاً من الصفر، و`level` طبقة السؤال (١ سهل · ٢ متوسط · ٣ صعب).

## إنشاء بنك وإلغاء تفعيله وحذفه

في لوحة المالك → البنوك → **إدارة البنوك**:

- **بنك جديد** (زرٌّ في ترويسة الصفحة): اسمٌ ومعرّفٌ بالإنجليزية (`seerah`). ويُولد
  فارغاً — ولا يُعرض لمن يُنشئ غرفةً حتى يدخله سؤالٌ واحدٌ على الأقل. وصورتُه في اللعبة
  `other` حتى تُنسخ له صورةٌ باسم معرّفه في `client/public/art/`.
  **ولا اسمان لبنكين** ولا معرّفان: الاسمُ المكرَّر يُردّ ولو اختلف تشكيلُه، والمعرّفُ
  يأبى غيرَ الحروف اللاتينية والأرقام والشرطة وأنت تكتبه.
- **إلغاء التفعيل** (أيقونة القفل): يُحجب البنك عن اللعبة ويبقى في اللوحة بأسئلته
  وإحصائه وبلاغاته، يُقرأ ويُحرَّر — ويظهر في الشريط الجانبيّ بقفلٍ إلى جانب اسمه.
  ولا يُلغى تفعيلُ بنكٍ تلعب به غرفةٌ قائمة.
- **الحذف** بضغطتين، الثانية للتأكيد: يُحفظ البنك بأسئلته كلها ثلاثين يوماً فيُرجَع كما كان من قائمة
  «البنوك المحذوفة». ولا يُحذف آخر بنك، ولا بنكٌ تستعمله غرفةٌ قائمة (احذف الغرفة أولاً
  من لوحة الغرف). والحذفُ في القاعدة فلا يُرجعه نشر.

## إضافة الأسئلة واستيرادها

في لوحة المالك → البنوك → **إضافة سؤال** (وزرُّ «أضف سؤالاً» في ترويسة بقيّة صفحات
البنوك ينقلك إليها). وهي غرفةُ انتظارٍ قبل البنك: لا يرى اللاعبُ ما فيها حتى يُعتمد.

- **النموذج فيه كلُّ الحقول** — السؤال، والإجابة الصحيحة، وثلاثةُ أخطاء، والبنك،
  والمستوى — **ولا يُلزمك إلا بالأوّلَين**. فمن عنده السؤالُ تامّاً كتبه مرّةً واحدة
  فدخل «ينتظر الاعتماد»، ومن ليس عنده إلا السؤالُ وجوابُه كتبهما ومضى. وEnter يحفظ
  ويُفرّغ الحقلين للسؤال الذي بعده، ويبقى البنكُ والمستوى على حالهما.
- **استيراد دفعة**: لصقاً في صندوقٍ أو ملفَّ CSV — سطرٌ لكل سؤال، السؤالُ ثم إجابتُه،
  يفصلهما Tab أو فاصلة أو `|`. وما زاد على العمودين قُرئ ولم يُطلب: ثلاثةُ أعمدةٍ
  للخيارات الخاطئة ثم عمودٌ للمستوى (`١/٢/٣` أو `سهل/متوسط/صعب`). وسطرُ العنوان
  يُتجاوَز إن وُجد. ويُعرض ما فُهم وما سقط ولماذا **قبل** أن يدخل شيء.
- **الصفُّ سطرٌ واحد**: السؤال، وإجابته، وقرصُ حاله، وقلمٌ يفتح المحرّر وسلّةٌ تحذف.
  وتفصيلُ النقص يُقرأ عند المرور على السطر.
- **الحالة**: «ناقص» ما ينقصه بنكٌ أو خيارٌ خاطئ أو مستوى، و«ينتظر الاعتماد» ما
  تمَّت تفاصيلُه. **ولا يُعتمد ناقصٌ** — ولا سؤالٌ فيه خطأٌ يكسر اللعبة.
- **المكرّر** يُعلَّم بشارةٍ تقول أين أصلُه (في بنكٍ أو في معلَّقٍ قبله) ولا يُرفض:
  ربّما كانت صيغتُك أحسنَ من صيغة البنك، فتعتمد هذه وتحذف تلك.
- **«اعتمد الجاهز»** في الترويسة يُدخل ما تمَّ منها دفعةً — والناقصُ يبقى.

## البنوك وأين تعيش

**نصُّ البنوك في PostgreSQL** (جدول `banks`) — فهو المرجع الذي يقرأه السيرفر ويكتب فيه،
وتحريرُك من اللوحة **لا يمحوه نشر**. وملفّات `server/banks/*.json` بذرةٌ ونسخةُ احتياط:

- **تُزرع مرّةً** حين تكون القاعدة فارغة (أول إقلاعٍ على قاعدةٍ جديدة) ولا تُزرع بعدها.
- **تُسحب إليها** بـ`pull-banks` أدناه، فيبقى في git نصٌّ مقروءٌ ونسخةٌ تُراجَع.

ولا يُستورد منها إلى القاعدة: كان في اللوحة زرٌّ يُدخل بنكاً له ملفٌّ وليس في القاعدة،
وآخرُ يُحلّ الملفَّ محلّ ما فيها — فرُفعا. فالبنكُ يُنشأ باسمه من اللوحة، وأسئلتُه
تُستورد لصقاً أو ملفَّ CSV، والثاني كان يمحو تحريراً جرى من اللوحة بملفٍّ قديم.

> [!NOTE]
> قبل هذا النقل كانت الملفّاتُ هي المرجع، فكان كلُّ نشرٍ يمحو ما حُرِّر من اللوحة
> ويُرجع المحذوف. وهي القصةُ نفسها التي نُقل بسببها سجلُّ الغرف من SQLite إلى
> PostgreSQL — والبنوك تبعتها.

## اسحب البنوك إلى المستودع

لتبقى نسخةٌ مقروءةٌ في git (للمراجعة والمقارنة، لا للنشر):

```bash
NABDA_URL=https://<موقعك> NABDA_OWNER_KEY=<مفتاحك> npm run pull-banks -- --dry   # يُخبر ولا يكتب
NABDA_URL=https://<موقعك> NABDA_OWNER_KEY=<مفتاحك> npm run pull-banks            # يكتب الملفّات
git diff server/banks && git add server/banks && git commit -m "سحبُ البنوك قبل النشر"
```

ويُمرَّر `--delete-missing` إن كنتَ قد حذفتَ بنكاً من اللوحة وأردتَ محوَ ملفِّه معه.

### استرجاعُ حذفٍ محاه نشرٌ قديم

قبل نقل البنوك إلى القاعدة كان النشرُ يمحو ما حُذف من اللوحة فترجع الأسئلة. وسجلُّ
التحرير في PostgreSQL نجا من ذلك كلّه، وفيه شهادةُ كل حذفٍ ثلاثين يوماً — فتُقرأ
ويُسقط ما تشهد به:

```bash
NABDA_URL=https://<موقعك> NABDA_OWNER_KEY=<مفتاحك> npm run pull-banks -- --minus-archive --dry
NABDA_URL=https://<موقعك> NABDA_OWNER_KEY=<مفتاحك> npm run pull-banks -- --minus-archive
```

فتعود الملفّاتُ إلى ما كانت عليه **بعد** تحريرك، ثم تُلتزَم ويُنشَر. ويطبع الأمرُ
ما أسقطه قبل أن يكتب، فتُراجعه. وما تجاوز ثلاثين يوماً كُنس من السجلّ فلا يُسترجَع.

افتح موقعك على `/console` وادخل بمفتاح المالك، ثم F12 ← Console، والصق:

```js
(async () => {
  const key = localStorage.getItem('nabda:owner');
  if (!key) { alert('ادخل لوحة المالك بمفتاحك أولاً'); return; }
  const r = await fetch('/api/console/bank/all', {
    headers: { 'x-nabda-key': encodeURIComponent(key) },
  });
  if (!r.ok) { alert('ردّ الموقع ' + r.status); return; }
  const { questions } = await r.json();
  if (!questions || !questions.length) { alert('لم يرجع سؤالٌ واحد'); return; }
  const banks = new Map();
  for (const q of questions) {
    if (!banks.has(q.bank)) banks.set(q.bank, { id: q.bank, name: q.bankName, questions: [] });
    const at = q.answer ?? 0;
    banks.get(q.bank).questions.push({
      q: q.q,
      options: [q.options[at], ...q.options.filter((_, i) => i !== at)],
      answer: 0,
      level: Number(q.level) || 2,
    });
  }
  for (const b of banks.values()) {
    const a = document.createElement('a');
    a.href = URL.createObjectURL(
      new Blob([JSON.stringify(b, null, 2) + '\n'], { type: 'application/json' }),
    );
    a.download = b.id + '.json';
    document.body.appendChild(a);
    a.click();
    a.remove();
    await new Promise((res) => setTimeout(res, 250));
  }
  console.log('تمّ: ' + banks.size + ' بنكاً · ' + questions.length + ' سؤالاً');
})();
```

ينزل ملفٌّ لكل بنك (اسمح بالتنزيلات المتعدّدة)، ثم ارفعها إلى `server/banks` من GitHub
(Add file ← Upload files) والتزمها. وهي الملفّات نفسها التي يُنتجها `pull-banks`.
