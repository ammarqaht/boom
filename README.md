# 💓 نبضة

لعبة مسابقة جماعية تُقام في قاعة. مجموعات تتنافس في وقت واحد، كل مجموعة معها عدّاد تنازلي
(نبضها). الإجابة الصحيحة تضيف وقتاً والخاطئة تخصم، وأول نبض يتوقف يُنهي الجولة على الجميع.

الهوية: مخطّط نبضات القلب — كلما نفد الوقت خفتت النبضات حتى يستقيم الخط ويسكن النبض.

## متجر البطاقات

بين الجولات تشتري المجموعات بطاقات بنقاطها — كل بطاقة **مرة واحدة** طوال اللعبة،
وتُطبَّق في الجولة التالية:

| البطاقة | الأثر | السعر |
|---|---|---|
| ⏱️ وقت إضافي | تبدأ الجولة القادمة بـ +5 ثوانٍ | 2 |
| ❄️ تجميد | تقفل مجموعة تختارها عن الإجابة 5 ثوانٍ في بداية الجولة (وعدّادها ينزل) — ويظهر لها اسم من جمّدها | 3 |
| ✕3 مضاعفة | نقاط جولتك القادمة ×3 — مجازفة: تضيع لو توقف نبضك | 4 |

## التشغيل محلياً

```bash
npm install          # اعتماديات السيرفر
npm run build        # بناء الواجهة
npm start            # http://localhost:3000
```

للتطوير مع إعادة التحميل التلقائي (نافذتان):

```bash
npm run dev          # السيرفر على 3000
npm run dev:client   # الواجهة على 5173 (تمرّر الطلبات إلى 3000)
```

## الاختبار

```bash
npm start            # في نافذة
npm test             # في أخرى — اختبار البطاقات ثم 52 فحصاً عبر سوكِت حقيقي
```

|---|---|---|
| التعريف | `/` | الجميع |
| المجموعة | `/play` | جهاز واحد لكل مجموعة |

## البنية

```
server/          سيرفر Node + Socket.IO — المرجع الوحيد للوقت والنتائج
  game.js        منطق اللعبة: الغرف، العدادات، النقاط
  banks/*.json   بنوك الأسئلة
client/          واجهة React + Vite + Tailwind
```

**قرارات تصميمية مهمة:**

- **الوقت يُحسب في السيرفر فقط** (نبضة كل 250 مللي‑ثانية). المتصفح يعرض ويُنعّم الحركة
  محلياً لكنه لا يقرر شيئاً — يمنع الغش ويوحّد كل الشاشات.
- **الإجابة الصحيحة لا تغادر السيرفر** قبل انتهاء الجولة، حتى لا تُقرأ من أدوات المطور.
- **الغرفة الجارية في الذاكرة** — وتُحذف الغرف الخاملة بعد ساعتين. أما السجلّ
  (الغرف وإحصاؤها، البلاغات، التعليقات، قياس الأسئلة) فيُكتب في `server/nabda.db`
  بـ`node:sqlite` المدمج — بلا مكتبةٍ ولا خادم قاعدة.

## النشر

> [!IMPORTANT]
> **شغّل نسخة واحدة فقط** (بلا autoscaling أو replicas). حالة اللعبة في ذاكرة العملية،
> فلو عملت نسختان قد ينضم فريق لواحدة وفريق لأخرى ولا يرى أحدهما الآخر.

المنصة يجب أن تدعم **الخوادم الدائمة و WebSocket** — فالمنصات الـ serverless لا تصلح،
لأن الحالة في الذاكرة و`setInterval` والاتصال الدائم لا تعيش فيها.

**ما تحتاجه المنصة:**

| | |
|---|---|
| البناء | `npm run build` |
| التشغيل | `npm start` |
| فحص الصحة | `/api/health` |
| Node | **٢٤ فأعلى** — `node:sqlite` لا يوجد قبلها (مثبَّت في `.node-version`) |
| النسخ | **واحدة فقط** — بلا autoscaling ولا replicas |
| قرصٌ دائم | يُركَّب على `server/` — وإلا ضاع السجلّ مع كل نشر |

السيرفر يقرأ المنفذ من `PORT` تلقائياً.

### متغيّرات البيئة

| المتغيّر | | |
|---|---|---|
| `NABDA_OWNER_KEY` | مفتاح لوحة المالك على `/console` | **اضبطه** — وإن تُرك فارغاً وُلّد مفتاحٌ مؤقّت عند كل تشغيل وطُبع في السجلّ، فيتبدّل مع كل نشر |
| `PORT` | منفذ السيرفر | تضبطه المنصة عادةً |
| `NABDA_DB` | مسار ملفّ القاعدة | اختياري — افتراضه `server/nabda.db` |

> [!WARNING]
> **القرص الدائم ليس ترفاً.** قاعدة البيانات ملفٌّ في `server/`. وأكثر المنصات
> تبني حاوياً جديداً عند كل نشر، فبلا قرصٍ دائم يبدأ السجلّ من الصفر في كل مرّة:
> تذهب إحصاءات الغرف وقياسُ الأسئلة والتعليقات. ركّب القرص على `server/`، أو
> وجّه `NABDA_DB` إلى مسارٍ داخل القرص المركَّب.

## إضافة بنك أسئلة

أنشئ ملفاً في `server/banks/` بهذا الشكل، وسيظهر تلقائياً في لوحة المسؤول:

```json
{
  "id": "sports",
  "name": "رياضة",
  "questions": [
    { "q": "كم عدد لاعبي فريق كرة القدم؟", "options": ["9", "10", "11", "12"], "answer": 2 }
  ]
}
```

`answer` رقم الخيار الصحيح بدءاً من الصفر.
